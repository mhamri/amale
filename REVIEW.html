Diagnostics available during a failure

bun amale/scripts/cli.ts diagnose <workspace> <run-id>
# Node fallback:
node amale/scripts/run.ts diagnose <workspace> <run-id>

Each operation has a durable ID, elapsed time, progress and outcome. API retries, pi process exits, tool progress, usage and failure messages survive independently of run revisions. Session paths and immutable artifacts preserve the detailed evidence. An unfinished trace means active or interrupted; inspect ownership before replaying it.

Costs distinguish OpenRouter response-reported values from pi estimates. Diagnostic fields redact known credentials; original authorized tool outputs and pi sessions may still contain project content.

Remaining practical limits

Whole-tree fingerprints conservatively invalidate unrelated changes. The host prepares workspaces, integrates changes and drives the loop. This is not a daemon. Native compaction is not replaced. No live vision transport, Kimi worker, macOS/Linux run, power-loss durability or production-scale stress test was performed. Host attestations are not independent proof. These are explicit limits, not hidden passes.
