Problem Statement

The user needs agents to finish correct work without spending most of the time on process, repeated reviews or reconstructing lost context. Existing workflows can remain in early phases, serialize independent changes, repeatedly consume large contexts and still miss consequential errors such as charging customers the wrong amount. Planning and review are useful only when they improve the delivered result.

The user also needs one portable entry point for Codex and Claude, with affordable workers selected for their actual capabilities. Large work must survive cleared sessions and restarts, while small changes must remain easy. The workflow must not depend on installing or chaining other skills.

Solution

Amale bundles discovery, specification, planning, research, implementation, review, documentation, verification and recovery into one adaptive flow. The invoking model owns the outcome. Jev selects bounded next actions from evidence-backed options; deterministic code enforces legal transitions and verification. Uncertain semantic judgments return to the invoking model.

Each invocation restores or creates a durable run, reconciles saved state with actual work, then selects the next useful action. Latest stable GLM Flash and DeepSeek Flash configurations do routine footwork through pi/OpenRouter. Configurable specialist routes and Kimi K3 handle justified deeper work. Fresh cross-model review and bounded repair escalation protect correctness without mandatory reviewer trees.

Small tasks use a compact brief. Large features retain phase outcomes, interface contracts and a dependency graph, with ready independent work executing concurrently. Human-facing designs and graphs use HTML. Persistent machine-maintained state provides continuity independently of the chat transcript.

Implementation Decisions

1. One owned flow

Bundle task-sized instructions for discovery, specification, architecture, planning, research, coding, visual work, review, documentation and acceptance. Load relevant portions on demand. Other skills are research references, not runtime dependencies. Jev, pi, OpenRouter, host tools and runtime packages remain explicit service/tool dependencies. Amale itself requires no issue-tracker integration.

2. Run and task contracts

A run records identity, workspace identity, schema revision, intent, authorization references, accepted decisions, non-goals, acceptance criteria, phase outcomes, task graph, artifacts, events, usage and unresolved blockers. Each task records its objective, dependencies, resource ownership, input contract, selected route, exact model configuration, state, attempts, output references and verification evidence. Replanning retains parentage and escalation history.

Task states distinguish proposed, ready, running, awaiting review, repairing, accepted and blocked work; a run distinguishes active, blocked and complete. Code validates transitions. Scheduling depends on accepted prerequisites and valid contracts, never prose claims or phase numbers. Completion means all required outcomes are supported by current evidence.

3. Jev decision interface

Supply a bounded question, state revision, relevant evidence, legal options and candidate metadata. Validate returned selections and uncertainty at runtime, record the chosen option and evidence, and reject stale or illegal responses. Independent questions sharing state may be batched; dependent questions require updated evidence. Reuse decisions only while their inputs remain valid.

Decision uses include discovery mode, next action, task route, model choice, context relevance, review lenses, finding disposition and claim support. The host proposes options and handles uncertain or invalid judgments. Service exhaustion receives the same recoverable failure handling as other required APIs; it does not silently erase the configured Jev policy. Code owns arithmetic, permissions, hashes, dependency checks, retry counters, resource locks and test truth.

4. Discovery and specification

Clear tasks proceed with a compact intent contract. Missing facts route to inspection, retrieval or an experiment. Unsettled intent and assumptions route to focused grilling; meaningful solution alternatives route to brainstorming. The main model leads user conversations; Flash workers gather facts. Ask prerequisite-ready questions with recommendations, preserve answers and wait only on work that actually depends on required input.

Built-in specification synthesis captures known outcomes, stories, constraints, interfaces, acceptance criteria, tests and exclusions without restarting the interview. Reflect newly co-designed intent for confirmation; reuse existing agreement and authorization. Avoid a mandatory sequence of spec, plan and execution approvals. Jev cannot invent consent or decide nondelegated user preferences.

5. Scale and scheduling

Large work uses phase outcomes and a validated dependency graph. Detail upcoming tasks from current evidence while retaining overall feature contracts; do not invent distant requirements. Reject duplicate task identifiers, missing dependencies and cycles. Group cohesive changes rather than creating one agent per file.

Dispatch independent ready tasks immediately within available capacity, using isolated workspaces. Serialize actual write conflicts, shared services and integration boundaries. Task-local checks run in isolation; combined checks run against integrated content. If isolation is unavailable, serialize conflicting work explicitly. No global wave barrier is implied by phase labels.

6. Model and provider routing

Prefer latest stable GLM Flash and DeepSeek Flash configurations for routine footwork. Role pools remain configurable for coding, frontend, visual inspection, research and mathematical work. Kimi K3 is a deeper-work candidate; known complexity can justify direct routing without a compulsory cheap failure. The host may do small coupled work when delegation overhead is greater.

Discover actual model access, tools, modalities, context limits and supported settings. Filter incompatible candidates in code. Supply Jev dated evidence cards separating user preferences, vendor claims, independent measurements and observed local outcomes. Calculate cost estimates in code; unknown subscription cost is not zero. Record exact model/provider/settings for each task, and refresh stale capability data without silently changing an active task's model.

Provider selection is distinct from model selection. Preserve required parameters and model-specific assistant/tool metadata. Do not silently strip images or substitute incompatible tools. Keep global pi defaults unchanged.

Conditional host effort

The same main model normally coordinates at medium effort and moves to high effort only when Jev identifies a concrete need for deeper architecture, diagnosis or final review. Preserve explicit user baseline overrides and use verified model-specific supported levels. Record requested effort separately from actual execution. Use an in-session mechanism where available, otherwise a bounded same-model higher-effort pass that returns to the baseline coordinator. Persist execution identity and result across resume, verify return to baseline, and do not claim that a separate pass changed the current session setting.

7. Cross-model review and escalation

DeepSeek-authored work receives a fresh GLM Flash review, and vice versa. Host/Kimi work receives an eligible different-family reviewer. A different provider for the same model does not satisfy independence. If an eligible reviewer is unavailable, select another configured capable family or report the blockage; do not pretend a same-model review is independent.

Give reviewers clean, read-only evidence: accepted intent, pinned changes, relevant standards, callers and check receipts, excluding the author's reasoning transcript and proposed verdict. Baseline lenses cover requirements, correctness, omissions and standards/simplicity, with separate Spec and Standards findings. Jev adds lenses only for actual changed behavior. Sensitive work can receive a focused reviewer in parallel.

Findings carry location, revision, reachable scenario, evidence, consequence and bounded correction. Distinguish inferred from verified behavior and introduced from unrelated inherited defects. Deduplicate without discarding evidence. Resolve serious disputes through focused evidence inspection or host diagnosis. A style preference alone is not a blocking defect.

Proposed configurable defaults: one baseline reviewer; one additional focused reviewer when warranted; at most two ordinary Flash repair cycles; then one Kimi diagnosis/repair cycle with independent verification; remaining blockers go to the main model for diagnosis and replanning. These numerical defaults were proposed during design and are not separately confirmed user-selected values.

Initial review is not a repair cycle. Re-review covers repair deltas and affected behavior. Escalate earlier when no progress or wrong architecture is evident. Counters survive commits, restarts and superficial renames. Bounds force a changed strategy, not abandonment or acceptance of broken work. Integration review focuses on new interactions and invalidated evidence.

8. Durable recovery

Use versioned persistent records, recoverable event ordering and atomic checkpoint replacement. Checkpoint before dispatch and after material results/decisions, not only at chat completion or compaction. Track live ownership and operation identities. Resume loads a compact index, reconciles actual workspace revisions and live workers, recovers abandoned ownership and invalidates affected evidence.

Interrupted side effects require checking their durable receipt and actual result before replay; ambiguous outcomes require resolution. Do not claim exactly-once external execution without supporting mechanisms. An interrupted user conversation preserves unanswered questions rather than interpreting elapsed time as agreement. A fresh session can select the run and continue without the previous transcript. Closing a session does not itself provide background execution.

9. Context and artifacts

Archive original artifacts before filtering context. Pin intent, constraints, accepted decisions, active tasks, unresolved failures and next actions. Build destination-specific packets from actual relevant excerpts with retrievable references. Jev selects optional context using content, not merely result length/status. Preserve tool-call pairing and required provider metadata.

Use supported pi filtering/compaction interfaces. Host hooks provide verified checkpoint/restoration where available; do not promise replacement of native host summaries through unsupported hooks. Correct recovery must remain possible from persisted state even when a hook did not fire. Skill links alone do not register hooks.

10. Verification and documentation

Verification receipts identify the exact artifact state, command or observation, result and acceptance claim. Changes to relevant inputs invalidate dependent receipts. A worker report or Jev confidence never overrides a failed required check. Money changes must verify expected amounts and reachable payment behavior. Concurrency defenses require an actual overlap, retry or shared-state path, not imagined future scope.

Every run keeps durable progress and evidence. Small tasks need brief criteria, while complex work maintains an integrated specification, contracts and graph. Research produces source-backed findings. Human-facing design and progress graphs use HTML; machine state uses structured records. Update existing repository documentation when changed behavior makes it inaccurate. Documentation is part of the flow, not an external skill invocation.

11. Continuation, portability and installation

Continue authorized work until verified completion or a genuine external blocker. Retry transient failures within bounded policy; persistent service failure or exhausted credits checkpoints the run and requests intervention. No artificial total-spending cap is introduced. Record model usage, wall time, repair cycles, repeated checks and verified outcomes.

Implement in TypeScript, prefer Bun and provide a tested Node fallback. Use portable path and subprocess APIs, respect case-sensitive filesystems and support Windows, macOS and Linux. Verify dependency versions against authoritative stable releases at implementation time, record source/date and regenerate lockfiles. Downgrade only after a reproducible compatibility failure.

Install one canonical skill with links in Claude and Codex, preserving existing Trellis links and global settings. Detect conflicts rather than overwrite unrelated targets. Make installation rerunnable, verify link resolution and report any platform privilege limitation. Register and verify hooks/extensions separately. Inherit the actual invoking model from supported host evidence; use explicit configuration when identity cannot be established.

Testing Decisions

Proposed primary seam, awaiting confirmation: exercise the public start/resume/run interface with controlled Jev, worker and host adapters. Assert observable outcomes, persisted recovery behavior and produced artifacts rather than private functions or exact prompt text.

The workspace currently contains a design viewer and research documents, not an orchestration runtime or an existing runtime test suite. Browser checks for the viewer are useful UI prior art only; they do not establish scheduling, recovery or model integration correctness. Introduce one high-level behavioral harness for those contracts, plus narrow live adapter checks where a simulated service cannot prove compatibility.

Out of Scope

  • Dependencies on external workflow skills, mandatory issue-tracker setup or a full Superpowers/BMAD pipeline.
  • A permanent best-model ranking, opaque automatic model routing beneath Jev, model training or autonomous routing-optimization infrastructure.
  • Mandatory one-agent-per-file or one-reviewer-per-lens dispatch, recursive reviewer trees, and full repeated reviews of unchanged evidence.
  • Speculative product requirements and safeguards without a requirement, observed failure or reachable failure path.
  • Universal background execution after the host session ends, unsupported replacement of host compaction or guaranteed exactly-once remote side effects.
  • Changing global pi defaults, replacing existing Trellis registration, or treating resumed work as authorization for unrelated actions.
  • Claims that the runtime, cross-platform integration, live model quality or cost savings are already implemented or proven.

Further Notes

This specification incorporates the latest requirement for one self-contained flow and supersedes earlier suggestions to invoke optional external skills. The accompanying interactive design remains the visual explanation of actors, routing, review, discovery and durable resume. Implementation followed this specification: the runtime is built, development tooling is installed, and the canonical skill is linked into Claude and Codex. Native host hooks are not installed; durable recovery uses explicit checkpoints and skill-driven resume.

Research references include Jev documentation, fast-jev-compaction, Superpowers, BMAD, and Matt Pocock skills, plus the supplied Trellis and locally inspected fresh-review material. These informed the proposed design; they are not prerequisites to run Amale.

The prior research record explicitly reports an incomplete full-site Jev documentation audit and no live comparative model evaluation. Complete relevant API/adapter verification during implementation. Model labels are preferences and candidates, not frozen release claims; resolve current stable identifiers and dependencies from authoritative sources at execution time.

The invoked to-spec workflow requests tracker setup through /setup-matt-pocock-skills and the ready-for-agent label on publication. That authoring workflow requirement does not become a dependency of Amale.
