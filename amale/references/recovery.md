# Durable resume and context

Run revisions and immutable artifacts live under the target workspace's neutral `.amale` directory. Always retain this directory when clearing chat or moving work. Do not commit credentials; none are intentionally stored by the runtime. Raw project outputs may contain sensitive data: constrain tool output to the task and use the host's existing data-handling rules.

`resume` checks worker process liveness on the recorded host and compares accepted workspace fingerprints. Interrupted work becomes blocked for reconciliation, not automatically ready. Inspect session logs and actual changes, determine whether pending side effects occurred, then `requeue` with evidence. A live worker is not stale merely because the chat was cleared. Remote ownership cannot be proven dead locally. `unlock` only handles demonstrably dead local owners.

Use `status` as the small restoration index. Pin intent, constraints, accepted decisions, current task, unresolved failures, escalation history and next actions. Retrieve large artifacts only for the active decision. Jev may choose relevant excerpts using actual content; archive originals with `save` first and retain references. Do not replace provider-specific messages with generic summaries. pi stores complete sessions, including tool and reasoning metadata.

This release uses explicit material-transition checkpoints and skill-driven restoration. No native Claude/Codex hooks are installed, and no native summary replacement is claimed. Run state is durable even if a final response or compaction hook never occurs. Before the host clears context, ensure current material progress has a recorded result or blocker. A new invocation lists/selects the run and resumes the loop without the old chat.

Credit exhaustion and persistent service failures preserve state. Transient API retries are bounded. Once credentials/credits/services are restored, resume the same run. An ambiguous operation result requires checking external reality before replay; this is not a guarantee of exactly-once remote execution. Closing the host does not keep a daemon running.

Use `diagnose` before retrying unexplained failures. Inspect the failed CLI/API/process timeline and its session/artifact references. An effort escalation that never launched uses `effort-reconcile` with `not-started`; an actually failed pass requires its exact execution ID, evidence that it stopped, and verified baseline restoration. See [effort](effort.md). Reconciliation records failure, never fabricates successful execution.

When a review workspace is missing or unreadable, `next` and `status` return `reconcile-workspace` while retaining independent ready candidates. Restore access, or run `resume` to block affected work for reconciliation. Resume preserves original artifacts and revision history, invalidates affected nonrunning verification without changing repair ancestry, and leaves live descendants owned by their workers. Their results cannot be accepted until prerequisite evidence is reconciled. The runtime does not restore or relocate a checkout automatically. After inspecting/restoring the checkout, `requeue` the blocked tasks with evidence; do not replay ambiguous side effects blindly.

For legacy running claims only, `reconcile-execution` accepts `{id, operation, confirmedStopped:true, evidence}`. Copy the current owner operation exactly (omit when no owner exists). First verify that task execution has stopped, even if its coordinator process remains alive. This trusted host attestation archives the prior task and releases ownership into blocked state; it does not kill any process or remove files. Inspect preserved artifacts, then use `requeue` and route again. Never assert stopped while work is still executing.
